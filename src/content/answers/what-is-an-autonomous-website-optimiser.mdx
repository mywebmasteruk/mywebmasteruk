## The three things it must do

A tool that only reports is an audit. A tool that only edits is a liability. An autonomous
optimiser has to close all three sides of the loop:

1. **Measure** — pull real performance data rather than a synthetic score. Search Console for
   demand and rankings, analytics for behaviour, a crawl for structural health, field data for
   Core Web Vitals.
2. **Act** — apply the change to the actual site, in version control, as a single reversible
   commit with a hypothesis attached.
3. **Prove** — wait a fixed measurement window, then compare against pages that were
   deliberately left alone.

Skip the third step and you have a system that generates activity and calls it progress.

## What separates it from an SEO tool

Traditional SEO software produces a list of issues and hands it to a human. The bottleneck is
never the list — it is the six weeks between the list and someone finding time to act on it.
An autonomous optimiser removes that gap for the class of changes where human judgement adds
nothing, and preserves it deliberately for the class where judgement is the whole point.

## The supervision is the product

Any language model can rewrite a title tag. The engineering that matters is everything around
it: a published boundary of permitted changes, build-time validation that rejects an invalid
edit, immutable deploys so rollback is instant, a stated hypothesis per change so the result
can be judged honestly, and a control group so the lift is measured rather than asserted.
